## The dataset

`data/stock_data.csv` — 25 MB, 230,111 rows, one row per ticker per trading day.

| Column | Notes |
|---|---|
| `Date` | `YYYY-MM-DD`, no time component |
| `Ticker` | 49 symbols, Yahoo Finance format |
| `Open` `High` `Low` `Close` | Raw prices, **local currency** |
| `Adj Close` | Split- and dividend-adjusted close |
| `Volume` | Shares traded |

Span: 2006-01-02 → 2026-02-20. No missing fields, no duplicate `(Date, Ticker)` pairs.
Parse with `parse_dates=["Date"]`; the file loads comfortably in memory.

## Gotchas that will silently ruin a chart

**1. Prices are in mixed currencies.** Never plot raw prices of different tickers on one
axis. Samsung (`005930.KS`) trades near ₩190,000 while Apple is around $200 — a shared
axis makes every non-KRW line a flat line at zero.

| Suffix | Market | Currency |
|---|---|---|
| `.KS` | Korea | KRW |
| `.HK` | Hong Kong | HKD |
| `.SW` | Switzerland | CHF |
| `.PA` | Paris | EUR |
| `.SR` | Saudi Arabia | SAR |
| *(none)* | US listings, incl. ADRs (BABA, TSM, ASML, AZN, HSBC, TM) | USD |

For cross-ticker comparison, normalize: index to 100 at a common start date, or plot
percentage returns. Both are currency-free and are usually the more honest chart anyway.

**2. Tickers start on different dates.** Only 33 of 49 span the full range. PLTR begins
2020-09-30, BABA 2014-09-19, META 2012-05-18, TSLA 2010-06-29. A naive `pivot` produces
leading `NaN`s — decide deliberately whether to drop those rows or start the x-axis where
the data actually starts. An index-to-100 chart must rebase to a date where *every*
plotted ticker exists, or the comparison is meaningless.

**3. Trading calendars don't align across exchanges.** Full-history row counts differ by
market: US 5,065 · Switzerland 5,070 · Paris 5,152 · Korea 4,972 · Hong Kong 4,964.
Different holidays. Joining on `Date` across markets leaves gaps — resample to weekly or
monthly before comparing across regions, or forward-fill explicitly and say so.

**4. `Close` is already split-adjusted — only dividends separate it from `Adj Close`.**
Verified against AAPL's real 4-for-1 split (2020-08-31): the file's `Close` for 2020-08-28
is $124.81, not the ~$499 that actually printed that day, so past splits are retroactively
baked into `Close` too, not just `Adj Close`. What's left between the two columns is
dividends only — confirmed zero gap for the non-dividend payers (AMD, AMZN, BRK-B, NFLX,
TSLA, PLTR). Still use `Adj Close` for returns/growth and `Close` for the literal traded
price on a given day, but don't describe `Close` as "raw" or "unadjusted" — it isn't, for
splits.

**5. The data runs to 2026-02-20.** Don't describe the tail as "today" or "current."

## Conventions

- Raw data in `data/` is read-only. Derived data goes to `data/processed/`, regenerated by
  a script rather than edited by hand.
- Every chart needs axis labels with units and currency, and a source/date-range note.
- State the transform in the title or caption when one is applied — "indexed to 100 at
  2015-01-02" is part of the chart, not a footnote.
- Prefer colorblind-safe palettes and direct line labels over legends with many series.

## Working style

- Build notebook/script code step by step, not one-shot. Add a cell or a small chunk,
  explain what it does, then move to the next piece so the team can follow along.
- No em-dashes in code comments.
- In notebook markdown cells, use lowercase bold text (`**heading**`) instead of `##`
  markdown headers.
- In notebook markdown/written answers, write column names and file paths as plain text,
  not backtick code-formatting. Reads like a student wrote it, not like AI output.
- Written interpretation in markdown cells goes as bullet points with a blank line between
  each point, not a single prose paragraph.
